Offline detection (stops false “offline” alerts)

A device or site is reported Offline only after the check failed every time it was re-tried and this happened on several checks in a row. One lost packet, one slow DNS answer or one busy moment never raises an Offline alert. While a failure is not yet confirmed, the last status stays on the dashboard.

Default 2 / 3 / 2. Example with the defaults and a 30-second check interval: Offline is confirmed after about 1–2 minutes of real silence, then the Alert trigger mode wait below still applies before anyone is emailed.

Global Escalation Defaults

Toggle each level ON to enable it. Default is all levels OFF for all devices. Use Apply to all devices to push these settings to every device at once.

💡 New devices always start with escalation disabled. Admin emails always receive alerts by default regardless of escalation.

Wait to confirm (default): don't email right away — only alert if the problem is still happening after "Level 1" time below elapses (default 60s, adjustable). A brief blip that recovers on its own (e.g. a few seconds of packet loss on a site that then comes back) still shows up in the Alert Event Log, it just won't email anyone — no need to get paged for a single small up/down spike.
Immediate: email the instant a device/site goes down or crosses a threshold, with no confirm delay at all.

Wait seconds, then alert

Separate from the trigger mode above, which only governs the first alert of a new problem. This governs repeat alerts — useful when a metric flaps in and out of a bad state every few seconds (a flaky link, a CPU spike that bounces around the threshold), which without a cooldown can trigger a new email on every single flap.
Immediate (default): no extra gap beyond what trigger mode / escalation levels already impose.
Cooldown: after any alert is sent, wait at least this many seconds before sending another for the same device and metric, no matter how many times it flaps in between. If you Acknowledge an alert, no further alerts are sent for it at all — even after the cooldown or the specified time — until it's genuinely resolved.
